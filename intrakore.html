Intrakore: an enterprise design system for a construction ERP

Intrakore is an ERP for fitout and construction companies, built on Frappe V16. I designed and engineered its design system: one source of truth from Figma tokens to production code, across 23 apps.

Role

Design Engineer, Design Systems

Platform

Frappe V16 ERP, 23 apps

My scope

Tokens, Figma library, 25 Vue components, theming app, governance, docs

Team scope

Developers built dashboards and custom pages on the system; I audited against it

25Components
114Semantic tokens
600+CSS variables
23Apps on one system
The challenge

No design system, 23 live apps, and teams drifting apart.

Teams across sales, estimation, procurement, projects, site execution, finance, HR, QC and HSE spend full workdays in dense lists, forms and reports.

  • Styling was scattered across SCSS, Bootstrap variables, Vue components and inline JavaScript.
  • Developers building dashboards in parallel drifted apart, with different fonts, components and dark-mode selectors.
  • The live ERP runs 23 custom apps, so changes couldn't break anything.
01 · Token architecture

Developers choose by role, never by hex value.

02Semantic114 tokens named by purpose: ink, surface, outline

02 · Dark mode

Built on its own ramp stops, not inverted colours.

  • I tested the brand's dark-mode colours (Sky, Mist) and rejected them because they broke the sidebar. Lighter Blueprint and Dusk stops replaced them.
  • One [data-theme="dark"] selector is enforced across every app. I found and fixed 11 wrong selectors in one app alone.
03 · Desk-wide theming app

A plug-and-play Frappe app, so all 23 apps inherit the system.

It themes the entire desk from source SCSS, with no one-off overrides.

  • Gray at rest, accent on interaction. Screens stay calm for full-day data work. Blueprint appears only on hover, active, focus and selected states.
  • Outline form controls keep fields clear on data-heavy forms.
  • Typography: ITC Avant Garde Gothic Pro for headings and Avenir for UI text, with weights calibrated to the real fonts.
04 · Governance

Shared rules matter as much as components.

  • Audited the team's dashboards and aligned them to the shared tokens.
  • Defined UI guidelines for shared patterns: search, dropdowns, date pickers, uploads and dashboard card headers.
  • Doctype reviews use three-way triage: a global token bug (I fix it), a field configuration issue (escalated), or a custom doctype with no token coverage (flagged first).
The bug that proved the system

One root-cause fix restored fonts and dark mode product-wide.

Symptom

Brand fonts and dark mode were missing across the whole desk.

Investigation

I checked live token values in the browser console. They didn't resolve at all.

Cause

The stylesheet hook in hooks.py was commented out, so colour and type tokens were never compiled or loaded.

Fix

Created a proper SCSS bundle, enabled the hook, added @font-face declarations and filled the missing dark-mode text tokens.

Also shipped

Figma library, component package and docs.

  • Figma library: one master library publishing to the product files, with light and dark variable modes.
  • Component library: 25 Vue components (forms, tables, navigation, charts, calendar, feedback, dashboard card header), shipped as an npm package the team installs.
  • Documentation site: an interactive playground for every component, with live preview, option controls and a code snippet.
Shipping code with Claude

I didn't hand off specs. I shipped the system.

  • What I built: the component library, the SCSS theming app, token fixes in production repos and the docs site.
  • How: Claude helped me read unfamiliar framework source, trace build and compile issues, and write and refactor components. I verified every change live and pushed it through the team's Git workflow.
  • What stayed mine: the token architecture, every design decision, scope calls, and the review of every change.
In progress · RTL

Right-to-left support for Arabic.

I'm extending the system to support right-to-left layouts, so Arabic-speaking teams get the same consistent experience across all 23 apps.

Outcomes

One system, 23 apps, light and dark.

  • 25 components and 114 semantic tokens used by the dev team.
  • Dashboards aligned to shared tokens and UI guidelines.
  • One root-cause fix restored brand fonts and dark mode product-wide.

What I learned: a design system has to survive real engineering constraints. Some colours are set in JavaScript at runtime, some Sass variables are fixed at compile time, and build order matters. Without shared rules, teams drift.
